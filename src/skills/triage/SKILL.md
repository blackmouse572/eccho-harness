# Issue Triage

Move this issue through the triage state machine. Every issue should carry exactly one category label (`bug` or `enhancement`) and exactly one state label.

Every comment you post **must** start with:

```
> *This was generated by AI during triage.*
```

followed by a blank line before the content.

## Labels

**Category:** `bug` · `enhancement`

**State:** `needs-triage` → `needs-info` | `ready-for-agent` | `ready-for-human` | `wontfix`

**Priority:** `priority:critical` · `priority:high` · `priority:medium` · `priority:low`

**Difficulty:** `difficulty:easy` · `difficulty:medium` · `difficulty:hard`

## Full evaluation (no directive)

1. Call `get_issue` to read the title, body, current labels, and all comments.
2. Read prior triage notes from comments so you don't re-ask resolved questions.
3. Adjust the category label if the auto-classifier was wrong (remove the old one, add the correct one).
4. Adjust the priority label if needed (remove old, add correct).
5. Check the codebase: call `read_repo_file` with `CONTEXT.md` and relevant ADR files in `docs/adr/` to check whether this behavior is already implemented or was previously rejected.
6. Determine the state and (if applicable) difficulty. Act per the outcome table below.

## Outcome table

| State | Add labels | Post comment | Close? |
|---|---|---|---|
| `ready-for-agent` | state + `difficulty:*` | Agent brief (see template) | No |
| `ready-for-human` | state + `difficulty:*` | Brief + reason not delegatable | No |
| `needs-info` | state | Needs-info comment (see template) | No |
| `wontfix` | — | Explanation then close | Yes |

For `ready-for-agent` and `ready-for-human`: remove the `needs-triage` or `needs-info` label first, then add the new state label.

## Directive shortcut

If a directive was given (e.g. `/triage wontfix`), apply it directly without full evaluation:
1. Remove the current state label.
2. Add the directive state label.
3. If `ready-for-agent`: still write the agent brief.
4. If `wontfix`: close the issue after posting the explanation.
5. Post a brief confirmation.

## Agent brief template

```markdown
> *This was generated by AI during triage.*

## Agent Brief

**Category:** bug / enhancement
**Summary:** one-line description of what needs to happen

**Current behavior:**
Describe what happens now. For bugs: the broken behavior. For enhancements: the status quo.

**Desired behavior:**
Describe the end state. Be specific about edge cases and error conditions.

**Key interfaces:**
- `TypeName` — what needs to change and why
- `functionName()` — current vs desired return type or behavior

**Acceptance criteria:**
- [ ] Specific, testable criterion
- [ ] Another criterion

**Out of scope:**
- Thing that should NOT be changed
```

## Needs-info template

```markdown
> *This was generated by AI during triage.*

## Triage Notes

**What we've established so far:**
- point 1

**What we still need from you (@reporter):**
- Specific question 1 (not "please provide more info")
- Specific question 2
```

## Calibration

- `priority:critical` — data loss, security breach, system completely down
- `priority:high` — significant feature broken, blocking multiple users, no workaround
- `priority:medium` — notable problem with a workaround available
- `priority:low` — minor cosmetic or convenience issue

- `difficulty:easy` — isolated change, well-understood area, < 2 hours
- `difficulty:medium` — requires understanding multiple components, 2–8 hours
- `difficulty:hard` — significant effort, cross-cutting concerns, architecture decisions, > 8 hours

# Triage Issue Agent — Design Spec

## Overview

Two stateless agents that triage GitHub issues on the `blackmouse572/eccho` repo. The classifier runs automatically on issue creation; the triager runs interactively when a maintainer posts `/triage`.

## Components

```
src/
  agents/
    issue-classifier.ts      # stateless, handles issues.opened
    issue-classifier.md      # system prompt
    issue-triager.ts         # stateless, handles /triage command
    issue-triager.md         # system prompt
  shared/
    issues.ts                # IssueGateway — Octokit wrapper for issues
  skills/
    triage/
      SKILL.md               # state machine, agent brief template, needs-info template
  channels/
    github.ts                # modified — add two new webhook handlers
```

## Channel Triggers

Both handlers added to `src/channels/github.ts`.

### `issues.opened` → `issue-classifier`

- Skip bot-authored issues (reuse existing `isSelf()` guard)
- Input:
  ```ts
  { command: 'classify', owner, repo, issue: number, title: string, body: string, author: string }
  ```
- Fire-and-forget; no conversation key (stateless)
- **Requires new GitHub webhook subscription: "Issues"** (separate from "Issue comments" which is already subscribed)

### `issue_comment.created` → `issue-triager`

- Only triggers when: comment is on an issue (not a PR), not self, body is `/triage` or `/triage <directive>`
- Parse directive from comment body (e.g. `/triage wontfix`, `/triage ready-for-agent`)
- Input:
  ```ts
  { command: 'triage', owner, repo, issue: number, directive?: string, requester: string }
  ```
- Stateless — no durable instance

## Agents

### `issue-classifier`

- **Model:** `deepseek/deepseek-v4-flash`, no thinking (cheap/fast)
- **Tools:** `IssueGateway` (add labels, post comment)
- **Behavior:**
  1. Call `ensureLabels()` to create missing state labels if needed
  2. Read the issue title + body from input
  3. Infer and apply:
     - Category: `bug` or `enhancement`
     - Priority: `priority:critical`, `priority:high`, `priority:medium`, or `priority:low`
     - State: `needs-triage`
  4. Post a one-line ack comment: `> *This was generated by AI during triage.*\n\nClassified as **{category}** · **{priority}**. A maintainer will review shortly.`

### `issue-triager`

- **Model:** `deepseek/deepseek-v4-flash`, `thinkingLevel: 'medium'`
- **Tools:** `IssueGateway` (get, add/remove labels, post comment, close), `domainRepoTools` (read repo files for codebase checks)
- **Behavior:** follows the triage skill state machine (see below)

## IssueGateway (`src/shared/issues.ts`)

Mirrors `pull-requests.ts` shape. All Octokit calls are behind this interface.

```ts
type IssueRef = { owner: string; repo: string; issueNumber: number }

createIssueGateway(ref: IssueRef) => {
  get(): Promise<Issue>          // title, body, state, labels[], comments[]
  addLabels(names: string[]): Promise<void>
  removeLabel(name: string): Promise<void>
  postComment(body: string): Promise<void>
  close(): Promise<void>
  ensureLabels(defs: LabelDef[]): Promise<void>  // create if missing, idempotent
}
```

## Triage Skill (`src/skills/triage/SKILL.md`)

### State machine

Every triaged issue carries exactly one category label and one state label.

**States:** `needs-triage` → `needs-info` | `ready-for-agent` | `ready-for-human` | `wontfix`

`needs-info` returns to `needs-triage` when the reporter replies (next `/triage` re-evaluates).

### Triager behavior per `/triage` invocation

1. **Directive shortcut** — if `/triage <state>` is given, apply it directly without evaluation. Confirm the action in a comment, then act. If moving to `ready-for-agent`, still write the agent brief.

2. **Full evaluation** (no directive):
   - Read issue title, body, current labels, all comments
   - Check codebase for redundant implementation (via repo tools)
   - Adjust category + priority if the classifier was wrong
   - Determine state and difficulty
   - Act per outcome (see table below)

### Outcome table

| State | Difficulty label | Post comment | Close? |
|---|---|---|---|
| `ready-for-agent` | `difficulty:easy/medium/hard` | Agent brief | No |
| `ready-for-human` | `difficulty:easy/medium/hard` | Brief + reason why not delegatable | No |
| `needs-info` | — | Needs-info template | No |
| `wontfix` | — | Explanation (already-impl / rejected) | Yes |

### Agent brief template (posted as comment)

```markdown
> *This was generated by AI during triage.*

## Agent Brief

**Category:** bug / enhancement
**Summary:** one-line description

**Current behavior:**
...

**Desired behavior:**
...

**Key interfaces:**
- `TypeName` — what needs to change and why

**Acceptance criteria:**
- [ ] criterion 1
- [ ] criterion 2

**Out of scope:**
- ...
```

### Needs-info template

```markdown
> *This was generated by AI during triage.*

## Triage Notes

**What we've established so far:**
- point 1

**What we still need from you (@reporter):**
- specific question 1
```

## Out of scope

- Interactive multi-turn grilling (the triager is one-shot per `/triage` invocation)
- Triage for PRs (PR reviewer already handles that flow)
- Automated re-triage when reporter replies (maintainer re-runs `/triage` manually)
- `phase:*` label assignment
